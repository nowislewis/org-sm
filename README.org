#+title: org-sm
#+author: Lewis Liu

Minimal incremental reading for org-mode, inspired by SuperMemo.

*Design rule: capture is dumb, review is smart.*  Capture only stores the raw
material — instant, no AI, no judgment.  Every AI action operates on an
*existing* card, once the material has proven worth the effort.

#+begin_example
  grab text ──► capture (verbatim) ──► review ──► refine / split (AI, optional)
                 M-z, C-c C-c                     C-c s A, C-c C-a
#+end_example

* Card Types

*topic* — repeated reading passage.  No grading; interval grows by A-Factor.

| Priority      | A-Factor | Behavior                       |
|---------------+----------+--------------------------------|
| =[#A]=        |      1.2 | slow growth, review frequently |
| =[#B]=        |      1.5 | moderate                       |
| =[#C]= / none |      1.8 | fast growth, fades out quickly |

*cloze* — fill-in-the-blank with ~{{answer}}~ markers, scheduled by
[[https://github.com/bohonghuang/fsrs.el][FSRS]].  Answers are hidden as
~[___]~ during review; rated again / hard / good / easy.

* Installation

Requires Emacs 29.1+, org 9.6+, [[https://github.com/bohonghuang/fsrs.el][fsrs]].

#+begin_src elisp
(use-package org-sm
  :hook (org-mode . org-sm-mode)
  :config
  (setq org-sm-directory "~/notes/")   ; inbox: sm-cards.org, created on demand
  (global-org-sm-read-mode 1))         ; M-z captures from any buffer

(with-eval-after-load 'org-sm
  (define-key org-mode-map (kbd "C-c s m")   #'org-sm-item-mark)
  (define-key org-mode-map (kbd "C-c s x")   #'org-sm-item-extract)
  (define-key org-mode-map (kbd "C-c s r")   #'org-sm-review-start)
  (define-key org-mode-map (kbd "C-c s SPC") #'org-sm-review-confirm)
  (define-key org-mode-map (kbd "C-c s d")   #'org-sm-item-dismiss)
  (define-key org-mode-map (kbd "C-c s q")   #'org-sm-review-abort)
  (define-key org-mode-map (kbd "C-c s t")   #'org-sm-tree)
  (define-key org-mode-map (kbd "C-c s A")   #'org-sm-card-workbench)
  (define-key global-map   (kbd "C-c s c")   #'org-sm-capture))
#+end_src

* Commands

| Command                 | Description                                     |
|-------------------------+-------------------------------------------------|
| ~org-sm-item-mark~      | Mark current heading as topic or cloze          |
| ~org-sm-item-extract~   | Extract selected region as child topic or cloze |
| ~org-sm-item-dismiss~   | Remove current item from SRS                    |
| ~org-sm-item-undismiss~ | Restore a dismissed item                        |
| ~org-sm-review-start~   | Start review session                            |
| ~org-sm-review-confirm~ | Confirm topic read / advance cloze state        |
| ~org-sm-review-abort~   | Abort current review session                    |
| ~org-sm-tree~           | Foldable aggregated tree of all cards           |
| ~org-sm-set-readpoint~  | Drop a read-point anchor; review jumps here     |
| ~org-sm-goto-source~    | Grep the vault for this card's source           |
| ~org-sm-capture~        | Capture region/clipboard into an editable buffer |
| ~org-sm-card-workbench~ | Refine and/or split the card at point           |
| ~org-sm-capture-commit~ | Commit a capture/workbench buffer (~C-c C-c~)   |

* Review Flow

- *topic:* ~review-start~ → read → ~review-confirm~ (reschedules, next item).
- *cloze:* ~review-start~ (hidden) → ~review-confirm~ (reveals) →
  ~review-confirm~ (rate).

Every prompt also offers *skip* (no change; stays due) and *dismiss*.
Intervals are computed from the scheduled date, so early/late reviews don't
distort spacing.

* Capture and card workbench

Both use one buffer type (~org-sm-capture-mode~) with one visual convention
and one commit command:

| In the buffer | Means                                                       |
|---------------+-------------------------------------------------------------|
| leading text  | one card's body (text before any ~**~ heading)              |
| each ~**~     | one more card                                               |
| ~C-c C-c~     | ~org-sm-capture-commit~: write back whichever are present    |
| ~C-c C-k~     | discard, touching nothing                                    |

** ~org-sm-capture~ (=M-z= / =C-c s c=)

Grabs the region (via ~M-w~, so pdf/nov/~reader-mode~ work too) or else the
clipboard into a side buffer, so you can see and edit it before writing.
Committing creates brand-new top-level topic cards, due tomorrow, in a single
inbox: an ~sm-cards~ heading in ~sm-cards.org~ under ~org-sm-directory~ (both
created on demand; change with ~org-sm-capture-file~ / ~org-sm-capture-olp~).
Refile into per-topic files yourself afterwards.

*No AI here.*  Capture stores exactly what you grabbed: at capture time you
don't yet know what the material is worth, the action must stay instant, and a
card you never revisit doesn't deserve tokens.

** ~org-sm-card-workbench~ (=C-c s A=)

Run it on the card you are reading.  The card's body is copied in as leading
text; nothing changes in the source until you commit.  Then ~C-c C-c~:

- the leading text replaces the card's body in place (type / schedule / id
  untouched);
- each ~**~ heading becomes a new scheduled *child* topic with a
  back-reference appended — existing children are left alone.

So one workbench covers a pure refine (no ~**~ headings), a pure split, or
both at once — by hand, or with the AI actions below.

* Extract

Select text, then ~org-sm-item-extract~:

- *topic* — the selection becomes the child body.
- *cloze* — the full parent body is copied to the child, selection wrapped as
  ~{{answer}}~.

The selection in the parent gains an ~[[id:...][title]]~ back-reference.

* Properties

| Property         | Type              | Description                     |
|------------------+-------------------+---------------------------------|
| ~SRS_TYPE~       | ~topic~ / ~cloze~ | Card type                       |
| ~SRS_LAST~       | ISO 8601          | Last review timestamp           |
| ~SRS_STATE~      | symbol            | FSRS state (cloze only)         |
| ~SRS_STABILITY~  | float             | FSRS stability (cloze only)     |
| ~SRS_DIFFICULTY~ | float             | FSRS difficulty (cloze only)    |
| ~SRS_STEP~       | int               | FSRS learning step (cloze only) |

~SCHEDULED~ is the due date for both types.

* AI assistant (org-sm-gptel)

Optional, powered by [[https://github.com/karthink/gptel][gptel]]:

#+begin_src elisp
(with-eval-after-load 'gptel
  (require 'org-sm-gptel)
  (define-key org-mode-map (kbd "C-c s ?") #'org-sm-gptel-explain))
#+end_src

All commands act on an *existing* card.  The workbench key is bound in
~org-sm-capture-mode-map~ but refuses to run in a plain capture buffer.

| Key       | Command                     | Action                                    |
|-----------+-----------------------------+-------------------------------------------|
| ~C-c s ?~ | ~org-sm-gptel-explain~      | Chat that explains this heading *to you*  |
| ~C-c C-a~ | ~org-sm-gptel-card-ai~      | Workbench: pick a mode, AI refines/splits |

*explain* — persistent side-window chat, why-before-what: motive and causal
chain first, definition second; ends by asking which word the sentence can't
live without.  It never makes cards for you.  Buffer reused on re-invoke.

*card-ai* — prompts for a mode, then ONE call does that mode's job:

- *refine* — clean up the leading body text only; cards always stay empty.
- *refine+subcard* — refine, and also judge whether anything is worth
  splitting off into child cards (empty is normal — most cards don't need
  any).  This was the previous, only, behaviour of this key.
- *简化 (simplify)* — cut the body to its essential core, more aggressively
  than refine; cards always stay empty.
- *自定义提示词 (custom)* — type your own instruction on the spot; used
  verbatim as the whole system prompt instead of any preset rule, still
  returning the same ~{body, cards}~ shape.

Every mode re-renders the buffer as leading text + ~**~ headings for you to
edit, then ~C-c C-c~ — which behaves identically regardless of mode: the
leading text always replaces the card's body, and every ~**~ heading always
becomes a child card.  Async; press ~C-c C-a~ again (any mode) to re-run.

Prompts are chosen by card type: *cloze* enforces the minimum-information
principle (one ~{{}}~, answer ≤ 5 words, why-type over what-type); *topic*
cleans prose for incremental reading (strip filler, resolve pronouns, keep
paragraphs and causal links, flag ~【需补充】~ when a conclusion lacks its
why).  Customize via ~org-sm-gptel-system-topic~ / ~-cloze~ (refine),
~-split~ (the child-splitting addendum used by refine+subcard),
~-simplify~ (the simplify prompt) and ~-explain~.

* Web front-end (org-sm-web)

Optional HTTP/JSON UI for reviewing from a phone browser; needs
[[https://github.com/skeeto/emacs-web-server][simple-httpd]].  A thin layer:
all scheduling and writing goes through the same org-sm functions the Emacs
commands use.

#+begin_src elisp
(org-sm-web-start)   ; autoloaded; prints the localhost + LAN URLs
#+end_src

| Variable          | Default     | Meaning                                     |
|-------------------+-------------+---------------------------------------------|
| ~org-sm-web-port~ | ~8842~      | Listen port                                 |
| ~org-sm-web-bind~ | ~"0.0.0.0"~ | ~"0.0.0.0"~ = LAN, ~"127.0.0.1"~ = local    |
| ~org-sm-web-root~ | ~web/~      | Static UI directory (~index.html~)          |

** Endpoints

| Method + path           | Params                          | Action                     |
|-------------------------+---------------------------------+----------------------------|
| ~GET  /api/queue~       | —                               | Due cards                  |
| ~GET  /api/card/:id~    | —                               | One card + cloze tokens    |
| ~POST /api/review/:id~  | ~rating=~ / ~action=~ [~days=~] | Grade / postpone / dismiss |
| ~POST /api/body/:id~    | ~body=~                         | Replace the card body      |
| ~POST /api/capture~     | ~type= body= [title=]~          | Create a new card          |
| ~POST /api/extract/:id~ | ~type= selected= start= end=~   | Create a child card        |
| ~POST /api/refine/:id~  | —                               | AI: rewritten body, *no write* |
| ~POST /api/card-ai/:id~ | —                               | AI: refine body + write child cards |

The AI endpoints need ~org-sm-gptel~; there is deliberately none on the
capture path.  ~/api/refine~ is a pure transform (the Edit textarea + ~Save~
stays the one write path), while ~/api/card-ai~ is the whole Emacs workbench
round collapsed into one request — hence the browser confirms first.
~:id~ must be the trailing path component (simple-httpd limitation).

** UI

- *cloze*: ~Show~, then ~Again~ / ~Hard~ / ~Good~ / ~Easy~.
- *topic*: ~Reschedule~ / ~Postpone~ (default 7 days) / ~Dismiss~.
- *edit*: ~Edit~ → textarea → ~Save~.  With ~org-sm-gptel~, ~AI Refine~
  refills the textarea first, so you preview before saving.
- *AI Refine + Split* (topic): refines the body and splits off child cards in
  one shot, then reloads the card.  Use ~Edit~ → ~AI Refine~ instead when you
  want a preview.
- *extract*: select text → floating ~Extract Topic~ / ~Extract Cloze~ menu.
  Cloze extraction is topic-cards-only (cloze bodies render as hidden tokens,
  so there are no raw-body offsets).
- *capture*: the ~＋~ button opens a sheet (type toggle, optional title, body
  prefilled from the clipboard when permitted).  One card, exactly as typed.

** Security

No authentication.  ~"0.0.0.0"~ exposes it to the whole LAN — keep it to
trusted networks, or bind ~"127.0.0.1"~ and tunnel (e.g. Tailscale).  Never
expose it to the public internet.
