#+title: org-sm
#+author: Lewis Liu

SuperMemo-style incremental reading for Org mode, built to stay plain-text and
low-friction over decades.

* Core Design & Invariants

1. *Plain Org files are the single source of truth.*  Every schedule, FSRS
   parameter, read-point (~[[rp:ID][📖]]~) and extraction link
   (~⌈…[[id:CHILD][<T>/<C>]]~) lives directly in ~.org~ files.  No external
   SQLite database, no coordinate sidecar, and no nightly ~auto-postpone~ job
   rewriting files behind your back.
2. *Capture is dumb; review is smart.*  Capturing stores raw text immediately
   with its source link and never calls AI.  AI only enters later, at review
   time, on cards that have proven worth the attention.
3. *One extraction primitive (=org-sm-extract=).*  Whether you extract a manual
   selection with ~M-z~, accept an AI underline on a card, or commit underlined
   spans in the workbench, every child card is created through
   ~org-sm-extract~: the parent body keeps an in-place
   ~⌈…[[id:CHILD][<T>/<C>]]~ highlight, and the child can always recover its
   surrounding parent context via ~org-sm-extract-origin~.
4. *Inside a card, every Org heading is a card.*  Plain section headings in
   imported articles are resolved once at entry by ~org-sm-sectionize~
   (rewritten to ~§ Title~ lines so the whole article stays one topic card).
5. *The AI points and polishes; you decide what becomes a card.*  The AI never
   fabricates ungrounded subcards or swaps your cloze targets.  It quotes
   verbatim spans as wavy underlines (hallucinated quotes and already-extracted
   ~⌈…[[id:…]]~ spans are dropped automatically) and leaves extraction and
   cloze formulation in your hands.

#+begin_example
  read (PDF/EPUB/Web/Org)
    │
    ├──► M-z / org-sm-capture ──► raw topic card (+ page:/nov: link)
    │
    ▼
  review queue (Review Clozes ──► 0.34 Topics ──► New Clozes)
    │
    ├──► x (suggest)     : AI underlines 1–3 verbatim spans; M-z extracts in place
    ├──► ? (explain)     : why-first chat with local + parent context & coordinates
    └──► w (workbench)   : edit or C-c C-a (AI rewrite + underlines) ──► C-c C-c commits
#+end_example

* Card Types & Priority

*topic* — reading / thinking passage (including your own open problem cards for
*Incremental Problem Solving*).  No pass/fail grading; each review multiplies
its interval by the priority A-Factor:

| Priority      | A-Factor | Behavior                                                    |
|---------------+----------+-------------------------------------------------------------|
| =[#A]=        |      1.2 | slow growth; returns every 1–2 days at the front of topics  |
| =[#B]= / none |      1.5 | default pace (`org-entry-get` treats no cookie as =B=)      |
| =[#C]=        |      1.8 | fast growth; default for bulk imports (*priority bias* guard) |

Press ~p~ during review (or ~org-sm-cycle-priority~) to step priority upward:
~C → B → A → C~.  Extracting from a ~[#C]~ card drops the ~C~ on the child
(extracting is the reader vouching for the passage); other cookies are
inherited.

*cloze* — active-recall card with one or more ~{{answer}}~ or
~{{answer::hint}}~ markers, scheduled by
[[https://github.com/bohonghuang/fsrs.el][FSRS]].
- Before reveal (~r~), ~{{answer}}~ is masked as ~[___]~ and ~{{answer::hint}}~
  shows its disambiguation cue as ~[___ · hint]~ (during normal Org reading,
  ~::hint~ is hidden by font-lock so the sentence reads naturally).
- On reveal (~r~), only ~[answer]~ is shown and the prompt offers FSRS ratings
  (~a~ again / ~h~ hard / ~g~ good / ~e~ easy), plus ~x~ (~explain~ — logs
  ~- explain~ to ~:LOGBOOK:~ and opens the card chat) and, on a leech, ~w~
  (~rewrite~ in the workbench).

* Properties

| Property         | Type              | Description                     |
|------------------+-------------------+---------------------------------|
| ~SRS_TYPE~       | ~topic~ / ~cloze~ | Card type                       |
| ~SRS_LAST~       | ISO 8601          | Last review timestamp           |
| ~SRS_STATE~      | symbol            | FSRS state (cloze only)         |
| ~SRS_STABILITY~  | float             | FSRS stability (cloze only)     |
| ~SRS_DIFFICULTY~ | float             | FSRS difficulty (cloze only)    |
| ~SRS_STEP~       | int               | FSRS learning step (cloze only) |

~SCHEDULED~ holds the due date for both types.

* Installation

Requires Emacs 29.1+, Org 9.6+, [[https://github.com/bohonghuang/fsrs.el][fsrs]], and ~rg~ (ripgrep) on ~PATH~.

#+begin_src elisp
(use-package org-sm
  :hook (org-mode . org-sm-mode)
  :config
  (setq org-sm-directory "~/notes/incremental/")
  (global-org-sm-read-mode 1)          ; M-z captures when no region/underline is active
  (with-eval-after-load 'gptel
    (require 'org-sm-gptel))
  (repeat-mode 1))
#+end_src

* Review Flow & Queue Ordering

** Three-lane derived queue (=org-sm-queue.el=)

Every entry point (light session, full session, branch review, and mobile web
UI) shares ~org-sm-queue-order~:

1. *Review clozes lead*, sorted by priority cookie first and then by forgetting
   risk (~late-days / interval-days~).  A late cloze loses recall along a
   forgetting curve; a late topic only waits to be read.
2. *Topics interleave up to ~org-sm-review-topic-proportion~ (0.34)* of served
   slots (2 topics in a 6-card light session), sorted by priority cookie and
   then longest-waiting first.  An ~[#A]~ topic (such as an active problem
   card) is guaranteed the very first topic slot.
3. *New (never-reviewed) clozes queue behind review clozes*, so a burst of new
   extractions never starves established memories.

The due pool is derived on the fly and never written back.  For sessions larger
than ~org-sm-review-light-size~, the mode line displays only the completed count
(~SM 12~ instead of ~SM 12/292~): because the most urgent cards are already at
the head of the queue, stopping at any point is safe.

** Read points: explicit ~📖~ anchor + automatic last-extract fallback

When a topic card is opened for review (in Emacs or the mobile web UI), point
jumps to where you left off via ~org-sm--readpoint-target~:
1. *Explicit bookmark wins:* if you placed a ~[[rp:ID][📖]]~ anchor with
   ~org-sm-set-readpoint~ (or double-tapped a paragraph in the web UI), review
   resumes there.
2. *Automatic fallback:* if no ~📖~ anchor exists, review automatically jumps to
   the end of the last extracted span (~⌈…[[id:…][<T>/<C>]]~) in the card body,
   so extracting a child card naturally advances your reading position without
   manual bookmarking.

** Stalled topics and leeches (=org-sm-card.el=)

- ~org-sm-stalled-p~: a topic reviewed ~org-sm-stall-review-threshold~ (8)
  times without producing a single child card.  The prompt flags ~⚠~ and puts
  ~w~ (workbench), ~x~ (suggest) and ~d~ (dismiss) up front.
- ~org-sm-leech-p~: a cloze rated ~again~ ~org-sm-leech-again-threshold~ (4)
  times.  The prompt flags ~↻~ and offers ~w~ to reformulate or simplify it.

** Neural review (=org-sm-neural.el=)

~org-sm-neural-start~ walks a card's semantic neighbourhood via spreading
activation: parent, children, siblings, and cards linked by ~id:~, up to
~org-sm-neural-size~.  Dismissed topic cards are traversed *through* without
being presented, acting as semantic bridges between sibling clozes.

* Capture, Workbench & Inline Underlines

Both plain capture and the card workbench use ~org-sm-capture-mode~, whose
header line stays visible at the top of the side window (the buffer visits no
file, so ~breadcrumb-mode~ leaves its header line alone).

** ~org-sm-capture~ (raw capture)

Grabs the active region or clipboard into `*org-sm capture*`.
- Leading text commits as a new topic card; any ~** Title~ headings commit as
  additional independent top-level topic cards.
- ~C-c C-t~ (~org-sm-capture-change-target~) switches the target ~.org~ file.
- Capturing from a PDF (~emureader~ / ~doc-view~), EPUB (~nov~) or web buffer
  automatically records a ~:SOURCE:~ property link on commit and routes the
  capture to the vault file that already cites that book.

** ~org-sm-card-workbench~ (refining and extracting in place)

Press ~w~ on any card to copy its body into a side workbench buffer:

- Edit the prose directly, or press ~C-c C-a~ (~org-sm-gptel-card-ai~) to let
  the AI rewrite the whole body — or *only the active region* when text is
  selected.
- Wavy underlines (~org-sm-pencils~) mark spans to extract as child topic cards
  on commit.  In topic ~refine~ mode the AI underlines 1–3 candidate spans; you
  can also select any text and press ~M-z~ to add an underline by hand.
- Navigate underlines with ~M-n~ (~org-sm-pencil-next~) and drop unwanted ones
  with ~M-k~ (~org-sm-pencil-dismiss~).  Underlines carry *no* overlay keymap,
  so Meow normal/insert single keys (~RET~, ~DEL~, ~TAB~) are never hijacked.
- Press ~C-c C-c~ (~org-sm-capture-commit~): first the edited body is written
  back to the parent card, then every surviving underline is extracted from end
  to start via ~org-sm-extract~, leaving ~⌈…[[id:…][<T>]]~ in place in the
  parent body and creating sibling child cards at ~level + 1~.

* AI Assistant (=org-sm-gptel.el=)

Powered by [[https://github.com/karthink/gptel][gptel]].  Every human-read
output (rewrite modes and ~explain~) appends ~org-sm-gptel-style~, distilled
from controlled technical Chinese (ASD-STE100: verbs over nominalisations, one
term per concept to prevent memory interference, no semicolon chains) and
anti-AI-tell rules (no staged "not X but Y", no summary closers, concrete
consequences instead of "crucial", causal connectives preserved).

| Key       | Command                | Scope in buffer                   | What it does                                                |
|-----------+------------------------+-----------------------------------+-------------------------------------------------------------|
| ~x~       | ~org-sm-gptel-suggest~ | active region, else screenful     | Underlines 1–3 verbatim spans; ~M-z~ extracts, ~M-k~ drops  |
| ~?~       | ~org-sm-gptel-explain~ | active region, else paragraph     | Opens/reuses card chat; sends local + parent + coords       |
| ~C-c C-a~ | ~org-sm-gptel-card-ai~ | active region, else workbench body | Rewrites prose (~refine~ / ~简化~ / custom) + underlines    |

- *Prioritising rules over isolated facts:* both ~suggest~ and workbench
  ~refine~ rank candidate spans by *transferable rules & causal mechanisms
  (when A leads to B) > concept boundaries > isolated conclusions*.
- *Preserving existing child links:* if a topic already contains
  ~⌈…[[id:…][<T>/<C>]]~ markers, prompts and ~org-sm-gptel--draw-picks~ keep
  those IDs intact and never draw new underlines over already-extracted spans.
- *Cloze target conservation & disambiguation hints:* on a ~cloze~ card,
  ~C-c C-a~ anchors to the existing ~{{...}}~ target(s) — whether a single blank
  or a multi-step progressive chain (~A → {{B}} → {{C}}~) — preserves any
  ~{{answer::hint}}~ cues, prefers placing single-blank targets at the end of
  the sentence (forcing full-premise reading before recall), and only trims
  surrounding fluff.  If a model response ever drops all ~{{...}}~ markers, the
  response is rejected before it can touch your draft.
- *Push neighbourhood + 3-step provenance + Pull on demand:*
  - ~C-c C-a~ (workbench rewrite) pushes deterministic neighbourhood context
    (800 chars before/after the active region in the workbench plus 800 chars
    before/after the extraction mark in the parent card via
    ~org-sm-extract-origin~, widening automatically across narrowed subtrees)
    with tools disabled for a fast single-turn JSON reply.
  - ~?~ (~org-sm-gptel-explain~) sends the stuck paragraph, ±1500 chars of card
    context, the parent extraction origin, and a one-line coordinate footer:
    ~【卡片坐标：文件 … 第 N 行，ID …，出处 …，笔记库 …】~.
  - Because child ~topic~ and ~cloze~ cards extracted under a parent inherit
    structure rather than duplicating metadata in their body,
    ~org-sm-gptel--card-provenance~ resolves ~出处~ in two steps (widening out
    of review narrowing):
    1. ~:SOURCE:~ on the card or its nearest ancestor heading (~(org-entry-get nil "SOURCE" t)~);
    2. the file's top-level ~#+source:~, ~#+SOURCE_URL:~, or ~#+reference:~
       keyword (e.g. a Citar/Denote bibliography note).
  - With ~org-sm-gptel-agent-preset~ enabled, no truncated 4000-char PDF dump or
    200 KB ~.org~ file is pre-attached on every turn: when local context is not
    enough, the agent pulls exact pages on demand via
    ~mutool draw -q -F txt -o - FILE N~ (including adjacent pages ~N-1~ / ~N+1~),
    queries Zotero fulltext via ~zotero-skill~, or searches the vault with
    ~Read~ / ~Grep~.

* Provenance & Importing (=org-sm-source.el=, =org-sm-import.el=)

- *PDF (~emureader~ / ~doc-view~):* ~M-z~ or ~org-sm-capture-page~ extracts the
  page's text layer synchronously via ~mutool draw -F txt~ and stores
  ~:SOURCE: [[page:/path/book.pdf::42][《book》p.42]]~ on commit.  Scanned pages
  without a text layer are refused (no OCR, to avoid silent typos in cards).
- *EPUB (~nov.el~) & Web (~eww~ / Copy-as-Org):* ~M-z~ records ~nov:~ or URL
  provenance and routes the card to the vault file that already cites the book
  (or matches ~#+reference:~).
- *Article/note import (~org-sm-import-file~, ~org-sm-import-url~):* converts
  HTML/Markdown/DOCX/TXT/Copy-as-Org into one long-form ~[#C]~ topic card with
  internal headings rewritten to ~§ TITLE~ lines via ~org-sm-sectionize~,
  localises images into a sibling ~-media/~ directory, and refuses duplicate
  imports via ~#+source:~.
- *External highlight importers (~org-sm-weread-import~, ~org-sm-zotero-import~):*
  both share ~org-sm-import-highlights~ — deduplicating against ~:SOURCE:~
  across the vault and inbox, marking new highlights ~[#C]~, and spreading due
  dates across days.

* Web Review & Mobile Editing (=org-sm-web.el=)

Local-network mobile UI (requires [[https://github.com/skeeto/emacs-web-server][simple-httpd]]):

#+begin_src elisp
(require 'org-sm-web)
(org-sm-web-start) ; prints http://LAN-IP:8842/
#+end_src

- Serves the same ~org-sm-queue-order~ queue (taking the first 6 cards for a
  light session).
- Supports cloze reveal/rating, topic rescheduling, inline selection extraction
  (~POST /api/extract/:id~), double-tap read-point updates
  (~POST /api/readpoint/:id~), priority buttons ~A~ / ~B~ / ~C~
  (~POST /api/priority/:id~), allowlisted image serving (~GET /api/image~), and
  revision-checked edits (~POST /api/patch/:id~).
- Shares ~org-sm-gptel~'s three AI actions asynchronously via
  ~httpd-discard-buffer~: wavy-underline extraction suggestions
  (~POST /api/ai/suggest/:id~), draft/selection rewriting in the edit sheet
  (~POST /api/ai/rewrite/:id~), and multi-turn why-first explanations
  (~POST /api/ai/explain/:id~).

* Extension Interfaces

- ~org-sm-card-at-point~ and ~org-sm-cards-in-file~ return a uniform plist:
  ~:type~, ~:id~, ~:title~, ~:priority~, ~:dismissed~, ~:interval-days~,
  ~:reviews~, ~:again-count~, ~:child-topics~, ~:child-clozes~.
- ~org-sm-after-review-functions~ and ~org-sm-after-card-change-functions~
  receive action plists (~:action~, ~:card~, ~:session~, ~:old-days~,
  ~:new-days~, ~:postpone-days~); observer errors are caught so they never
  abort a completed write.
- HUD customisation hooks: ~org-sm-banner-function~,
  ~org-sm-feedback-function~, ~org-sm-finish-function~, ~org-sm-review-keys-hint~,
  and ~org-sm-set-header-line~ (used by ~org-ladder~).
