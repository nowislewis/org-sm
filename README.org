#+title: org-sm
#+author: Lewis Liu

Minimal incremental reading for org-mode, inspired by SuperMemo.

* Card Types

*topic* — repeated reading passage.  No grading; interval grows by A-Factor each review.

| Priority      | A-Factor | Behavior                       |
|---------------+----------+--------------------------------|
| =[#A]=        |      1.2 | slow growth, review frequently |
| =[#B]=        |      1.5 | moderate                       |
| =[#C]= / none |      1.8 | fast growth, fades out quickly |

*cloze* — fill-in-the-blank with ~{{answer}}~ markers, scheduled by [[https://github.com/bohonghuang/fsrs.el][FSRS]].
Answers are hidden as ~[___]~ during review; rated again / hard / good / easy.

* Installation

Requires Emacs 29.1+, org 9.6+, [[https://github.com/bohonghuang/fsrs.el][fsrs]].

#+begin_src elisp
(use-package org-sm
  :hook (org-mode . org-sm-mode)
  :config
  (setq org-sm-directory "~/notes/")
  ;; Cards go to an "sm-cards" heading in sm-cards.org under
  ;; org-sm-directory by default (created on demand).  Override with
  ;; org-sm-capture-file / org-sm-capture-olp if you want a different inbox.
  (global-org-sm-read-mode 1))  ; M-z captures region/clipboard from any buffer
#+end_src

Suggested keybindings:

#+begin_src elisp
(with-eval-after-load 'org-sm

  (define-key org-mode-map (kbd "C-c s x")   #'org-sm-item-extract)
  (define-key org-mode-map (kbd "C-c s r")   #'org-sm-review-start)
  (define-key org-mode-map (kbd "C-c s SPC") #'org-sm-review-confirm)
  (define-key org-mode-map (kbd "C-c s d")   #'org-sm-item-dismiss)
  (define-key org-mode-map (kbd "C-c s q")   #'org-sm-review-abort)
  (define-key org-mode-map (kbd "C-c s t")   #'org-sm-tree)
  (define-key global-map   (kbd "C-c s c")   #'org-sm-capture))
#+end_src

* Commands

| Command                 | Description                                     |
|-------------------------+-------------------------------------------------|
| ~org-sm-item-mark~      | Mark current heading as topic or cloze          |
| ~org-sm-item-extract~   | Extract selected region as child topic or cloze |
| ~org-sm-item-dismiss~   | Remove current item from SRS                    |
| ~org-sm-item-undismiss~ | Restore a dismissed item                        |
| ~org-sm-review-start~   | Start review session                            |
| ~org-sm-review-confirm~ | Confirm topic read / advance cloze state        |
| ~org-sm-review-abort~   | Abort current review session                    |
| ~org-sm-tree~           | Foldable aggregated tree of all cards           |
| ~org-sm-set-readpoint~  | Drop a read-point anchor; review jumps here     |
| ~org-sm-goto-source~    | Grep the vault for this card's source           |
| ~org-sm-capture~        | Capture region/clipboard into an editable buffer |

* Review Flow

*Topic:* ~review-start~ → read → ~review-confirm~ (reschedules, next item).

*Cloze:* ~review-start~ (answers hidden) → ~review-confirm~ (reveals) → ~review-confirm~ (rate).

Every review prompt also offers *skip* and *dismiss*.  *skip* advances to the
next card with no change — the card stays due and reappears next session.

Intervals are calculated from the scheduled date, so early/late reviews don't distort spacing.

* Capture

~org-sm-capture~ grabs a region or clipboard content into a lightweight
editable side buffer (~org-sm-capture-mode~) so you can see and adjust it
before writing.  With a region active or in ~reader-mode~, it triggers ~M-w~
first (works in any buffer: pdf, nov, etc.), otherwise reads the clipboard.

Inside the capture buffer:

| Key       | Action                                                    |
|-----------+-----------------------------------------------------------|
| ~C-c C-c~ | Write the card(s) and close                               |
| ~C-c C-k~ | Discard                                                   |
| ~C-c C-a~ | (with ~org-sm-gptel~) AI-split the content into cards     |
| ~C-c C-i~ | (with ~org-sm-gptel~) refine the card at point            |

The buffer holds either plain text (one card) or ~**~ headings (one card
each — e.g. after an AI split); ~C-c C-c~ writes them all as topics via the
pure ~org-sm--capture~.  Add cards by typing a ~**~ heading; delete by
editing.

~org-sm-capture~ writes to a single inbox with no prompt: an ~sm-cards~
heading in ~sm-cards.org~ under ~org-sm-directory~ (both created on demand).
Just ~M-z~ -> edit -> ~C-c C-c~.  Sort cards into per-topic files yourself
afterwards (plain org refile).  Change the inbox with ~org-sm-capture-file~ /
~org-sm-capture-olp~.  ~global-org-sm-read-mode~ binds ~M-z~ globally to
~org-sm-capture~.

* Extract

Select text, then call ~org-sm-item-extract~:

- *topic* — selected text becomes the child body.
- *cloze* — full parent body copied to child; selection wrapped as ~{{answer}}~.

The selection in the parent is replaced with an ~[[id:...][title]]~ link.

* Properties

| Property         | Type              | Description                     |
|------------------+-------------------+---------------------------------|
| ~SRS_TYPE~       | ~topic~ / ~cloze~ | Card type                       |
| ~SRS_LAST~       | ISO 8601          | Last review timestamp           |
| ~SRS_STATE~      | symbol            | FSRS state (cloze only)         |
| ~SRS_STABILITY~  | float             | FSRS stability (cloze only)     |
| ~SRS_DIFFICULTY~ | float             | FSRS difficulty (cloze only)    |
| ~SRS_STEP~       | int               | FSRS learning step (cloze only) |

~SCHEDULED~ is the due date for both types.

* AI Assistant (org-sm-gptel)

Optional extension powered by [[https://github.com/karthink/gptel][gptel]].

#+begin_src elisp
(with-eval-after-load 'gptel
  (require 'org-sm-gptel)
  (define-key org-mode-map (kbd "C-c s ?") #'org-sm-gptel-explain)
  (define-key org-mode-map (kbd "C-c s i") #'org-sm-gptel-refine)
  (define-key org-mode-map (kbd "C-c s A") #'org-sm-gptel-extract-split))
#+end_src

Loading ~org-sm-gptel~ also adds two keys inside every ~org-sm-capture-mode~
buffer: ~C-c C-a~ (AI-split the content) and ~C-c C-i~ (refine the card at
point).

** Commands

*** ~org-sm-gptel-explain~ (=C-c s ?=)

Opens a persistent side-window chat where the AI explains the current heading
*to you* — use when you're stuck during review.  Follows a *why-before-what*
order: it first explains the design motive / causal chain (why the thing exists
and why it's built this way), and only then states what it is.  Closes with a
single question asking which word the sentence can't live without, leaving the
card-making to you.  The chat buffer ~*org-sm-explain: <heading>*~ is reused on
re-invoke.

*** ~org-sm-gptel-refine~ (=C-c s i=)

Refines the current heading body in-place with a single async AI request,
then replaces the body in place — no ~gptel-rewrite~ dependency, no diff /
accept step.  Don't like the result?  Just ~undo~.  Works on any org
heading, including an ~org-sm-capture-mode~ buffer.

The system prompt is chosen automatically by card type:

- *cloze* → enforces the minimum-information principle (one ~{{}}~ per
  card, answer ≤ 5 words, split multi-fact content), preferring a
  why-type cloze (mechanism/cause/result) over a what-type one when the
  source has a causal relation.
- *topic / unset* → cleans prose for incremental reading: strips filler,
  resolves pronoun ambiguity, preserves paragraph structure (not a summary),
  and never deletes causal links (flags ~【需补充】~ when a conclusion lacks its why).

This mirrors the web front-end's plain refill-and-edit flow (see
~org-sm-gptel-rewrite-text~, its synchronous counterpart) — both share one
request core, ~org-sm-gptel--rewrite-request~.

Typical workflow after ~org-sm-capture~ or ~org-sm-item-extract~:
1. Land on the new child heading.
2. ~C-c s i~ to refine raw content in place.
3. ~undo~ if you don't like it, otherwise continue.

*** AI capture (=C-c C-a= inside a capture buffer)

~org-sm-gptel-capture-ai~ is bound to ~C-c C-a~ in every ~org-sm-capture-mode~
buffer.  It sends the buffer's current content to the AI, which *cleans and
splits* it into one or more Topic cards (per ~org-sm-gptel-system-capture~:
strip filler, keep causal chains, make implicit logic explicit, no new
facts), then replaces the buffer with the resulting ~**~ headings for you to
edit and commit with ~C-c C-c~.  Asynchronous.  Press ~C-c C-a~ again to
re-split; ~C-u C-c C-a~ adds a one-off instruction (e.g. split finer / merge).

This keeps one flow for both plain and AI capture: ~C-c s c~ -> look -> either
~C-c C-c~ (as-is) or ~C-c C-a~ then edit then ~C-c C-c~.

*** ~org-sm-gptel-extract-split~ (=C-c s A=)

Split the card you are *reading* into child cards.  Run it with point on an
SRS card (e.g. during review): it sends the card's body to the AI (per
~org-sm-gptel-system-split~), which proposes several atomic child topics --
*preferring reusable concept / claim cards* (high memory-reuse value), but
following the content's own structure when narrative/procedural/list content
fits better.  Each becomes a scheduled child topic and a back-reference is
appended to the parent body; the parent card is kept.  With prefix arg,
prompt for a one-off extra instruction.

Both AI capture and extract-split share one core
(~org-sm-gptel-split-text~ / ~org-sm-gptel--split-request~), which the web
~/api/split~ endpoint also calls -- one source of truth for “text -> cards”.

Relevant options:

| Variable                      | Meaning                                          |
|-------------------------------+--------------------------------------------------|
| ~org-sm-gptel-system-capture~ | System prompt for AI capture (clean + split)     |
| ~org-sm-gptel-system-split~   | System prompt for extract-split (concept-biased) |


* Web front-end (org-sm-web)

Optional HTTP/JSON front-end for reviewing cards from a phone browser.  A thin
layer: all scheduling is delegated to org-sm's pure functions
(~org-sm--{topic,cloze}-grade~, ~org-sm--dismiss~, ~org-sm--extract~), so it and
the Emacs commands share one source of truth.  Requires
[[https://github.com/skeeto/emacs-web-server][simple-httpd]].

** Usage

#+begin_src elisp
(require 'org-sm-web)          ; or rely on the autoloaded command
(org-sm-web-start)            ; M-x org-sm-web-start   (autoloaded)
;; open the printed URL on any device on the same LAN
#+end_src

~org-sm-web-start~ prints the localhost and LAN URLs.  Add the page to the iOS
home screen for a full-screen PWA.

** Configuration

| Variable            | Default     | Meaning                                        |
|---------------------+-------------+------------------------------------------------|
| ~org-sm-web-port~   | ~8842~      | Listen port (must be ≥ 1024 unless root).      |
| ~org-sm-web-bind~   | ~"0.0.0.0"~ | Bind address.  ~"0.0.0.0"~ = LAN; ~"127.0.0.1"~ = local only. |
| ~org-sm-web-root~   | ~web/~      | Static UI directory (served ~index.html~).     |

The queue is read from ~(org-sm-files)~, the same live scan of ~org-sm-directory~
the Emacs commands use.

** Endpoints

| Method + path        | Params                              | Action                          |
|----------------------+-------------------------------------+---------------------------------|
| ~GET  /api/queue~     | —                                   | Due cards ~[{id,type,priority,title}]~ |
| ~GET  /api/card/:id~  | —                                   | One card ~{id,type,title,body,clozes}~ |
| ~POST /api/review/:id~ | ~rating=~ / ~action=~ [~&days=~]     | Grade / reschedule / postpone / dismiss |
| ~POST /api/body/:id~   | ~body=~                             | Replace the card body (refine)  |
| ~POST /api/capture~    | ~type= body= [title=]~              | Create a new card via ~org-sm--capture~ |
| ~POST /api/split~      | ~text= [extra=]~                    | AI-split text into cards (no write; needs ~org-sm-gptel~) |
| ~POST /api/refine/:id~  | —                                  | AI-rewrite the card body in place (needs ~org-sm-gptel~) |
| ~POST /api/extract-split/:id~ | —                            | AI-split the card into children (needs ~org-sm-gptel~) |
| ~POST /api/extract/:id~ | ~type= selected= start= end=~      | Create a child card via ~org-sm--extract~ |

~/api/capture~ writes into ~org-sm-capture-file~ / ~org-sm-capture-olp~ (the same
target the Emacs ~org-sm-capture~ command uses), schedules the card for
tomorrow, and returns its new ~id~.  Cloze bodies must contain at least one
~{{answer}}~ marker.

~/api/split~ is a pure transform: it returns the AI's proposed
~{cards:[{title,body}]}~ *without writing anything*.  The UI shows them for
editing, then creates each via ~/api/capture~ — so there is still one write
path.  It shares its core with the Emacs AI capture / extract-split.

~/api/refine~ and ~/api/extract-split~ mirror the Emacs ~org-sm-gptel-refine~ /
~org-sm-gptel-extract-split~ commands, sharing the same AI cores
(~org-sm-gptel-rewrite-text~ / ~org-sm-gptel-split-text~):
- ~/api/refine~ is a *pure transform* like ~/api/split~ — it returns the
  rewritten body *without writing anything*; the existing Edit textarea +
  ~Save~ (~/api/body/:id~) remains the one write path.  This matches Emacs
  ~org-sm-gptel-refine~, which also only edits the buffer (no auto-save).
- ~/api/extract-split~ *does* write — it creates the child cards and
  appends back-references to the parent, then saves, matching Emacs
  ~org-sm-gptel-extract-split~ (which also auto-saves, since it's a
  structural change spanning multiple new headings).

Note: ~:id~ must be the trailing path component — simple-httpd only supports
trailing template parameters, hence ~/api/body/:id~ rather than ~/api/card/:id/body~.

** UI

Button labels mirror the Emacs wording:

- *cloze*: ~Show~ to reveal, then ~Again~ / ~Hard~ / ~Good~ / ~Easy~.
- *topic*: ~Reschedule~ / ~Postpone~ (prompts for days, default 7) / ~Dismiss~.
- *edit*: ~Edit~ turns the body into a textarea; ~Save~ writes it back.
- *extract* (incremental reading): select text → a floating menu offers
  ~Extract Topic~ / ~Extract Cloze~; the selection becomes a scheduled child
  card with a back-reference link.  Cloze extraction is topic-cards-only, since
  cloze cards render ~{{}}~ as hidden tokens (no raw-body offsets available).
- *capture* (new card): the ~＋~ button in the header opens a sheet with a
  Topic/Cloze toggle, an optional title, and a body box (pre-filled from the
  clipboard when the browser grants permission).  ~Save card~ posts to
  ~/api/capture~ and the due count refreshes.
- *AI Split* (topic only, needs ~org-sm-gptel~): in the capture sheet, ~AI
  Split~ sends the body to ~/api/split~ and refills the box with the proposed
  cards as ~# TITLE~ blocks.  Edit them, then ~Save card~ writes each one —
  mirroring the Emacs ~C-c C-a~ flow.
- *AI Refine* (needs ~org-sm-gptel~): while reviewing, ~Edit~ then ~AI
  Refine~ sends the current body to ~/api/refine/:id~ and refills the
  textarea with the result; edit further if you like, then ~Save~.  No
  diff — mirrors the Emacs ~org-sm-gptel-refine~ (undo-to-revert) flow.
- *AI Split card* (needs ~org-sm-gptel~): while reviewing, ~AI Split card~
  posts to ~/api/extract-split/:id~, which splits the card into several
  child topics (preferring reusable concept/claim cards) and appends
  back-references; the current card is reloaded to show the links.
  Mirrors the Emacs ~org-sm-gptel-extract-split~.

** Security

No authentication.  Binding ~"0.0.0.0"~ exposes it to the whole LAN — keep that
to trusted networks.  For remote access use a private overlay (e.g. Tailscale),
or set ~org-sm-web-bind~ to ~"127.0.0.1"~ and tunnel.  Never expose it to the
public internet.
